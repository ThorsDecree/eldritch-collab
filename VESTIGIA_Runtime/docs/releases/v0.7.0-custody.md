## 3. Remaining live Windows gate

`v0.7.0-validation.md` contains the authoritative redacted trust-boundary ledger. The following cases must be exercised on the Windows Discord deployment before final publication:

1. `source.visibility=hidden`
2. `source.visibility=allowlisted_only`
3. `source.visibility=mentions_only`
4. `source.visibility=all_channel`
5. oversized ambient message envelope preservation
6. reaction to triggering message
7. reaction to visible ambient message
8. rejection of reaction to a non-visible message ID
9. reaction removal
10. failed reaction delivery receipt
11. private-image challenge creation
12. later resident confirmation opened by another participant
13. wrong interface or channel rejection
14. challenge replay rejection
15. expired challenge rejection

For each row, record only:

- pass/fail;
- UTC timestamp;
- deployed Runtime commit;
- redacted receipt/event reference;
- a short failure note when applicable.

Do not record message content, participant IDs, channel IDs, tokens, private image prompts, or private image bytes.

### Gate rule

The release MAY proceed only when every row is either:

- `Pass`, with a redacted evidence reference; or
- `Not applicable`, with an explicit reason tied to the exact v0.7.0 behavior.

Deterministic tests, screenshots without receipts, or operator recollection do not replace this ledger.

## 4. Final publication sequence

After the live ledger is complete:

1. Commit the completed redacted ledger on this custody branch.
2. Run ordinary documentation CI and obtain maintainer review.
3. Merge the custody documentation PR to `main`.
4. Re-download the preserved v0.7.0 artifact from Actions.
5. Verify the artifact ZIP SHA-256 and contained wheel/sdist hashes against section 2.
6. Create annotated or lightweight tag `v0.7.0` at the validated v0.7.0 release commit selected in section 1, not at current v0.8 `main`.
7. Create GitHub Release `VESTIGIA Runtime v0.7.0 — The Resident's Drawers` from that tag.
8. Attach exactly:
   - `vestigia_runtime-0.7.0-py3-none-any.whl`
   - `vestigia_runtime-0.7.0.tar.gz`
   - `SHA256SUMS.txt`
9. Download the public release attachments and verify both payload hashes again.
10. Update `README.md` and `ROADMAP.md` so `v0.7.0` is described as both development-canon historical release and publicly published distribution.
11. Close issue #5 as completed.

## 5. Release-note minimum

The public release notes should include:

- the release name and compatibility floor;
- Windows and Python 3.11/3.14 validation statement;
- the genuine v0.6.1 upgrade/pack/restore validation statement;
- a link to `v0.7.0-validation.md`;
- the SHA-256 values for the wheel and source distribution;
- the security boundary that v0.7.0 does not grant unrestricted host execution;
- a note that later v0.8 development work is not part of this tagged release.

## 6. Explicit non-actions

Do not:

- tag current v0.8 `main` as `v0.7.0`;
- rebuild a new wheel and call it the previously verified artifact;
- mark pending live checks as passed from deterministic CI;
- include secrets or private Discord content in the evidence ledger;
- close issue #5 before the public tag, release, attachments, and hash verification exist.
