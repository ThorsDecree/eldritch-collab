# VESTIGIA Runtime v0.7.0 validation record

Status: release candidate

This record keeps four different kinds of evidence separate. A passing deterministic test is not
reported as a live Discord canary, and a fresh current-version home is not reported as an upgrade
from the previous stable release.

No secret values, participant identifiers, channel identifiers, resident prose, message content,
or private image bytes belong in this record.

## 1. Deterministic CI

The Windows matrix runs on Python 3.11 and Python 3.14.

It verifies:

- source compilation;
- the complete deterministic test suite;
- package construction on Python 3.11;
- clean isolated installation of the built wheel with the `discord` and `tokens` extras;
- `pip check` after both development and isolated-wheel installation;
- imported stable version `0.7.0`.

The package-smoke job hashes and uploads the exact files it built and installed:

```text
vestigia_runtime-0.7.0-py3-none-any.whl
vestigia_runtime-0.7.0.tar.gz
SHA256SUMS.txt
```

The workflow artifact is named:

```text
vestigia-runtime-0.7.0-<commit-sha>
```

The post-merge `main` artifact, rather than a later local rebuild, is the release-attachment
candidate.

The CI upgrade job constructs the specimen with the genuine v0.6.1 repository commit:

```text

```

The specimen is synthetic and contains no resident archive. Under the v0.6.1 source it creates:

- one fake private image and its artifact records;

The release candidate then:

```text

→ completes a current fake-provider turn

```

The evidence artifact is named:

```text

```

It contains only:


The JSON evidence records source/target runtime and schema versions, redacted identity/room hashes,
per-table counts, selected stable IDs and content hashes, runtime state, the home-pack SHA-256,
manifest file count, and the result of restore hash verification. It contains no secret values or
resident content.

The release gate is satisfied only when this job passes on the final release-candidate commit.

## 5. Release custody sequence

After all gates pass:

```text
merge the final release PR
→ wait for `main` CI
→ download the artifact for the exact `main` commit
→ verify `SHA256SUMS.txt`
→ tag that exact commit as `v0.7.0`
→ create the GitHub release
→ attach the preserved wheel, source distribution, and checksums
→ close issue #5
→ mark roadmap 0.7.0 as released
```

A wheel rebuilt after the verified CI run is a new artifact and must not be represented as the
file already tested by that run.
