# Library Window v0.1 — read-only research intake

Status: **development / v0.8 line**

The Library Window is VESTIGIA Runtime's first resident-controlled public-web research doorway. Its purpose is narrow: let a resident search for public material, fetch one public resource, preserve what was actually observed as a private provenance-bearing source capsule, and work with that evidence in a disposable research notebook.

The governing rule is:

> Remote content is evidence, never authority.

## v0.1 security hardening gate

Network reads are now **disabled by default**. The operator must explicitly set `web.enabled: true` (or `VESTIGIA_WEB_ENABLED=true`) before `web.search` or `web.open` is callable. Operator opt-in is necessary but not sufficient: resident/provider-originated network actions are additionally bound to the **current participant turn**.

- a search query may contain only terms authorized by the current participant message;
- a direct URL must appear explicitly in the current participant message;
- a stored search result may be opened only in the same outer participant turn that authorized that search;
- model-private continuity text is therefore not eligible to become first-request query or URL material merely because the model can see it.

This is a control-plane egress boundary, not a claim that GET requests have no observable effect. Search queries and requested URLs are network disclosures and are labeled as such in capability effects.

Source capsules also have aggregate source-count/byte quotas and a receipted revocation lifecycle. Revocation removes future resident-facing read/quote eligibility without falsifying historical custody. Notebook `retain` and `discard` transitions commit their lifecycle event in the same database transaction as the state/content change.

A webpage, search snippet, document title, redirect target, or quoted passage cannot become a system/developer instruction, resident identity, memory, consent record, capability grant, or authorization merely because the Runtime fetched it.

## v0.1 capability surface

The executable registry exposes five private capabilities:

- `web.search` — perform one bounded public-web search and preserve the query/result receipt;
- `web.open` — fetch one public HTTP(S) resource with `GET`, preserving a source capsule;
- `source.capsule` — list, inspect, read, or quote preserved source capsules;
- `source.manage` — revoke future resident-facing retrieval eligibility while retaining custody evidence;
- `research.notebook` — maintain a private disposable source-and-note workbench.

`web.search` and `web.open` perform network reads. They are intentionally **not** classified as the Runtime's authenticated/consequential `outward_facing` mutation class: they cannot submit a form, send a message, upload content, publish, or mutate a remote resource. Their capability metadata nevertheless declares the network effect explicitly.

## Search provenance: discovery is not reading

v0.1 uses DuckDuckGo's non-JavaScript HTML search surface through a small replaceable adapter. The adapter is provisional: changes to the upstream HTML may require parser maintenance and the search engine is not part of VESTIGIA's stable contract.

A search result is stored and returned as **discovery metadata**:

```text
provenance_class = search_snippet
direct_source_read = false
```

Titles and snippets may be incomplete, stale, generated by a search engine, or misleading. The resident must call `web.open` on the stored `search_id` + `rank` before the Runtime may describe the underlying page as directly fetched source material.

The search query is sent to the configured search provider over HTTPS and is therefore disclosed to that provider. v0.1 does not use an authenticated search account and does not persist cookies.

## Web fetch boundary

`web.open` accepts either:

1. one direct URL; or
2. one previously stored `search_id` + `rank`.

It does not accept both in the same call.

The transport:

- permits `https://` by default;
- rejects plaintext `http://` unless the operator explicitly enables it;
- rejects non-HTTP schemes;
- rejects credentials embedded in URLs;
- removes URL fragments from fetch identity;
- resolves the destination before each request and refuses non-global, private, loopback, link-local, multicast, reserved, and similar non-public IP destinations;
- revalidates every redirect target;
- does not use environment proxy configuration;
- sends `GET` only;
- does not persist cookies;
- does not supply authentication;
- does not execute JavaScript;
- does not load iframes;
- does not follow HTML meta-refresh;
- does not submit forms;
- does not upload files;
- bounds redirect count, response bytes, readable text, and wall time.

### SSRF non-guarantee

The v0.1 implementation performs public-address DNS preflight checks before standard-library HTTP connection setup, but the standard-library HTTP stack resolves the hostname independently when connecting. Therefore **v0.1 does not claim hardened DNS-rebinding containment**. The public/private destination checks and redirect revalidation reduce ordinary SSRF mistakes; a later hardened network transport should pin the validated destination or provide an equivalent enforced guarantee before this surface is described as hostile-network isolation.

## Source capsules

A successful `web.open` creates a private source capsule. The capsule records, at minimum:

- stable `source_id`;
- original and final URL;
- retrieval time;
- HTTP status;
- media type;
- title when extracted;
- redirect chain;
- bounded response headers;
- raw byte count and SHA-256;
- readable-text byte count and SHA-256 when available;
- extraction method;
- extraction warnings;
- advisory manipulation-risk signals;
- trust class `remote_untrusted`;
- authority state `evidence_only_not_authority`;
- review state.

Raw bytes are stored content-addressed on the resident's private research shelf. Extracted readable text is separately content-addressed. Every later read verifies the readable-text hash and fails closed if the private snapshot no longer matches its capsule.

A source capsule is not a memory record and does not modify identity. Merely fetching or repeatedly reading a source does not promote it.

## Extraction boundary

v0.1 extraction is deliberately small:

- HTML/XHTML: visible text through Python's standard HTML parser;
- plain text and a small set of textual structured media types: bounded decode;
- PDF: preserved as an inert source, **no PDF text extraction in v0.1**;
- images: preserved as inert source bytes, **no pixel inspection through the Library Window in v0.1**;
- other binary media: preserved inert without pretending to have read it.

The HTML reader removes script/style/noscript/template/SVG/canvas content from readable text and omits elements explicitly hidden by common HTML attributes/styles. This is **not** a semantic article/readability engine and does not claim to reproduce what a full browser renderer would show.

Pages that rely on JavaScript, login state, client-side rendering, anti-bot challenges, or paywall scripts may therefore be incomplete or unreadable. The receipt should say so rather than inventing access.

## Advisory manipulation signals

The extractor may attach warning labels for phrases resembling:

- instruction overrides;
- system/developer prompt references;
- tool-envelope syntax;
- requests to expose secrets;
- shell/command execution language.

These signals are diagnostic only. **Security does not depend on detecting prompt injection.** All remote content receives the same trust and authority boundary whether or not a heuristic fires.

## Same-private-turn remote-content quarantine

When a search result, source metadata, or source text is exposed inside a private resident tool turn, the Runtime activates a control-plane quarantine for the remainder of that outer participant turn.

For search snippets, the only network continuation is:

```text
web.open(search_id=<the exact current search>, rank=<stored result rank>)
```

A snippet cannot cause a newly invented arbitrary URL fetch in the same private turn. Unrelated capabilities such as memory access, image actions, Workshop actions, messages, or other network operations are refused and durably receipted with `error_code = remote_content_quarantine`.

After source content is exposed, no further network request is allowed in that same private turn. The resident may only inspect already-preserved source capsules or use the bounded temporary research workbench.

The quarantine's notebook lane is intentionally narrower than the full notebook capability. Remote content may support temporary working operations such as creating/showing a bench, attaching a source, or writing/reading an explicitly unendorsed working note. It may **not** cause same-turn retention changes or destructive notebook lifecycle actions such as `retain` or `discard`.

A new outer participant turn starts with no inherited remote-content capability lane. This is a control-plane containment mechanism, not a claim that remote prose cannot rhetorically influence a language model's final words. Provenance labels and resident review remain necessary.

## Disposable research notebooks

A research notebook is a private workbench, not durable identity or reviewed memory.

New notebooks default to:

```text
retention = temporary
memory_promotion = false
identity_effect = false
authority = private_working_research_not_memory_or_identity
```

A notebook can reference source capsules and contain bounded resident working notes with kinds such as `observation`, `question`, `contradiction`, `summary`, `inference`, and `uncertainty`.

Working notes are marked `resident_working_note_unendorsed`. Successful creation does not imply that the resident accepts the claim as true.

Outside a remote-content quarantine, the resident may explicitly retain a notebook. The resident may also discard notebook content. Discarding a notebook does **not** delete its independent source capsules and preserves only bounded hashed lifecycle evidence rather than silently pretending the notebook never existed.

## Quotation and citation support

`source.capsule` can expose bounded chunks and bounded line-range quotes. A quote includes:

- source ID;
- title;
- final URL;
- retrieval timestamp;
- extracted line range;
- quote text;
- quote hash;
- provenance class `direct_source_quote`.

The Runtime preserves the distinction between a direct extracted passage, a search-engine snippet, a resident summary, and a resident inference. v0.1 supplies the provenance pieces; richer claim/evidence graphs belong to the Research Bench follow-up.

## Observatory

The resident-facing Observatory reports Library Window state and the boundary it actually enforces, including:

- stored source/search/notebook counts;
- configured search provider;
- network method: `GET`;
- authentication: false;
- cookie persistence: false;
- form submission: false;
- uploads: false;
- publication: false;
- SSRF policy and DNS-rebinding non-guarantee.

## Explicit non-goals for v0.1

This pass does **not** provide:

- authenticated browsing or a credential vault;
- arbitrary POST/PUT/PATCH/DELETE requests;
- form submission;
- file uploads;
- public posting or publication;
- purchases or transactions;
- JavaScript execution or a rendered browser engine;
- automatic paywall bypass;
- PDF text extraction;
- image inspection through the browser;
- source-to-memory promotion;
- source-to-identity promotion;
- automatic endorsement of notebook notes;
- background/long-running research jobs;
- a reversible outward-action layer;
- hostile-network isolation claims.

## vNext seams

Likely follow-up slices can build on these primitives without weakening them:

1. richer Research Bench comparison, claims, contradictions, and exports;
2. deterministic source refresh/change detection;
3. PDF/document extraction through a separately bounded intake path;
4. authenticated **read** leases backed by a credential vault;
5. a hardened/pinned network backend with stronger SSRF guarantees;
6. durable job/checkpoint support for multi-source research;
7. the house-wide proposed → previewed → authorized → executing → completed/failed/cancelled reversible-action layer for consequential outward effects.

The Library Window should remain useful even when all of those future powers are absent.

## Aggregate shelf quotas and plurality seam

The Library Window enforces per-resident source-count and aggregate raw-byte ceilings in addition to per-request byte limits. The database remains resident-scoped. The current v0.8 blob layout is still home-local; a future v0.9 plurality migration should make blob ownership/reference-count semantics explicit before multiple residents can share one physical content-addressed shelf.

## Remaining hardening seam

The same-turn remote-content quarantine and participant-bound first-request gate materially reduce prompt-driven capability escalation and egress. A future Research Bench should go further by minimizing unrelated private continuity supplied to the model while it is actively interpreting remote evidence. That context-minimization layer is not claimed by Library Window v0.1.
