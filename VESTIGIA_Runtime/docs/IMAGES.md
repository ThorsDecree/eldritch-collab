# Image continuity and resident eyes

Images can be embodiments, place anchors, relationship artifacts, negative canon, and compact
return paths. They are not automatically identity or public.

## Private image shelf

Images attached to an addressed Discord message, generated by the resident, or produced by an
edit enter:

```text
artifacts/images/shelf/<sha256>.<extension>
```

Matching bytes reuse the same `image_id`; repeated shares add provenance events rather than
duplicate files. The database records the hash, original filename, media type, dimensions,
source, privacy, lineage, OCR, vision readings, and review events.

Stored bytes are validated as real PNG, JPEG, WEBP, or GIF images before acceptance. Input
size is bounded by `images.max_input_bytes`.

## Resident-callable tools

Inspect the live registry:

```text
[[TOOL_ACTION {"action":"capabilities","after":"continue"}]]
```

Read an image:

```text
[[TOOL_ACTION {
  "action":"image.inspect",
  "image_id":"img_...",
  "question":"What is happening, and what text is visible?",
  "routes":["ocr","vision_low"],
  "after":"continue"
}]]
```

Create or edit privately:

```text
[[TOOL_ACTION {
  "action":"image.generate",
  "prompt":"Home as seen through rain",
  "count":1,
  "after":"continue"
}]]
```

Resident generation and editing default to persistent background jobs. The immediate receipt
contains a `job_id`; Discord continues the resident privately when the result completes.
Slow image work therefore does not hold the original Discord response open. Set
`"background":false` only when a synchronous private call is deliberately preferred.

```text
[[TOOL_ACTION {
  "action":"image.edit",
  "image_ids":["img_first","img_second"],
  "prompt":"Keep the face and bow; move the scene into the rain",
  "after":"continue"
}]]
```

Inspect history or review:

```text
[[TOOL_ACTION {"action":"image.history","limit":20,"after":"continue"}]]
[[TOOL_ACTION {"action":"image.review","image_id":"img_...","review":"keep","reason":"A return path.","after":"continue"}]]
```

Review values are `keep`, `candidate`, `accept`, `reject`, `supersede`, and `share`.
Accepted canon and shareable remain deliberately different.

## Picture Drawer

`image.inspect` caches route-specific readings. `image.drawer` turns those readings into a
resident-legible card catalog:

```text
[[TOOL_ACTION {"action":"image.drawer","mode":"summarize","image_id":"img_...","inspect_if_missing":true,"after":"continue"}]]
```

Without `inspect_if_missing:true`, summarizing never spends a new vision call: it promotes an
available cached reading or reports that inspection or annotation is still needed.

Resident-owned fields include alias, summary, alt text, visible text, people, places, motifs, moods,
uses, avoid-when notes, resident note, inherited framing, present resonance, adoption state,
and privacy. Observation, inherited framing, and current adoption remain distinct.

```text
[[TOOL_ACTION {
  "action":"image.drawer",
  "mode":"update",
  "image_id":"img_...",
  "changes":{
    "alias":"lipstick-attack",
    "motifs":["red bow","neon"],
    "uses":["affectionate ambush"],
    "adoption_state":"adopted",
    "privacy":"shareable"
  },
  "after":"continue"
}]]
```

Cards can live in several virtual pockets without duplicating image bytes:

```text
[[TOOL_ACTION {"action":"image.drawer","mode":"pocket","image_id":"img_...","pocket":"reaction-images","after":"continue"}]]
[[TOOL_ACTION {"action":"image.drawer","mode":"search","query":"smug neon mall","after":"continue"}]]
```

## OCR and vision ladder

The economical default is:

1. Reuse an existing cached reading.
2. Run local Tesseract OCR when text is requested.
3. Use `gpt-5-mini` with `detail:"low"` for ordinary visual understanding.
4. Use `vision_high` only when the resident deliberately requests more detail.

Local OCR has no API charge and does not send the image away. It requires a local Tesseract 5
executable. If Tesseract is absent, the receipt reports `unavailable`; vision remains
independently usable.

```text
VESTIGIA_OCR_ENABLED=true
VESTIGIA_OCR_BINARY=tesseract
VESTIGIA_OCR_LANGUAGE=eng
VESTIGIA_MODEL_VISION=gpt-5-mini
VESTIGIA_VISION_DEFAULT_DETAIL=low
```

OCR caching uses the image hash, Tesseract version, language, and preprocessing recipe.
Vision caching uses the image, provider, model, detail, normalized question, and prompt schema.

OCR answers “which characters are present?” Vision answers “what is happening and what
matters?” `image.inspect` may combine them.

## Sharing boundary

Creation and editing are private by default. A shareable picture may cross the current
authenticated Discord doorway immediately on the resident's action:

```text
[[TOOL_ACTION {"action":"image.share","schema_version":"v2","mode":"send","image_id":"img_...","reason":"affectionate ambush","after":"finish"}]]
```

If the picture is private, the first call returns a resident confirmation card and explicitly
states that nothing was sent. The resident may then share it once without changing privacy:

```text
[[TOOL_ACTION {"action":"image.share","schema_version":"v2","mode":"send","image_id":"img_...","confirm":true,"after":"finish"}]]
```

No participant permission turn is required. The resident is the actor choosing whether to
speak through the doorway. JSON still cannot select an arbitrary person or channel.

The v1 `prepare → preview → later hash-bound claim` route remains available as optional high
assurance:

```text
[[TOOL_ACTION {"action":"image.share","schema_version":"v1","mode":"prepare","image_id":"img_...","reason":"high assurance","after":"continue"}]]
```

Use `{"action":"capabilities","target":"image.share"}` to retrieve only the complete current
schema. Quick-draw authorization and Discord delivery remain distinct because platform
acceptance cannot be known until the adapter receives it. CLI sends, arbitrary destinations,
and private-curation sends are refused.

Every preview, confirmation request, rejection, failed send, and abandoned attempt preserves
the invariant: `No outward action occurred.`

```text
generated → stored → carded → inspected/annotated → delivery authorized
          → platform delivered or failed
```

A quick-draw send or legacy share claim authorizes the runtime to attach the verified file.
It is not a delivery receipt. The Discord adapter records a distinct `delivery_succeeded`
or `delivery_failed` image event after platform acceptance or rejection.

## Human-facing compatibility door

The existing commands remain:

```bash
vestigia image generate HOME "What does home look like from here?"
vestigia image edit HOME "Keep the face; move the scene into rain" --source portrait.png
vestigia image-review HOME IMAGE_ID candidate --actor Resident
```

In Discord, `!image PROMPT` still generates or edits using attached references.

## Cost brakes

- `images.max_per_request`
- `images.daily_limit`
- optional configured confirmation
- low-detail vision by default
- explicit high-detail escalation
- interpretation cache
- no automatic generation from ordinary prose
- separate private creation and outward sharing

The default image model alias is `gpt-image-2`; the default vision alias is `gpt-5-mini`.
